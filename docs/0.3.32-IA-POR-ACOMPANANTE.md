# TrackIA 0.3.32 · IA por acompañante

Entrega de la historia US11 del SDD 004 (`specs/004-trackia-experience/`, opcional). Cada acompañante
puede usar el modelo del perfil o uno propio, sin duplicar claves.

## Cómo funciona

- **Por defecto**, todos los acompañantes usan la IA configurada en Ajustes → Inteligencia artificial.
- **Excepción**: en esa misma pantalla, «Por acompañante» lista cada acompañante con «Por defecto» o su
  modelo. Al tocar uno se puede escribir otro modelo **del mismo proveedor** o volver al predeterminado.
- La excepción se guarda en `trackia_companion_settings.ai_override` como
  `{"provider":"openai","modelId":"gpt-ligero"}`. Solo proveedor y modelo: cualquier otra clave (una
  API key, por ejemplo) hace que el valor se rechace al leerlo.
- Las **credenciales siguen siendo del perfil** y viven solo en `flutter_secure_storage`. La base de
  datos nunca guarda claves.
- El chat de un acompañante carga la configuración con `AiSettingsStore(exception: …)`: es la del
  perfil con el modelo de la excepción y el protocolo recalculado para ese modelo
  (`AiConfig.withOverride`). Las pantallas de IA y de ajustes siguen leyendo la del perfil
  (`loadDefault`).

## Reglas

- Una excepción de **otro proveedor** se ignora y se usa la configuración del perfil: el perfil no
  tiene credenciales para ese otro proveedor.
- Un valor dañado en la base se trata como «sin excepción» y deja un `debugPrint` con el tipo del
  error; el acompañante sigue funcionando con la IA del perfil.
- Cambiar la IA del perfil (proveedor o clave) no borra las excepciones; si el proveedor deja de
  coincidir, dejan de aplicarse hasta que vuelva a coincidir.
- La comprobación de «conexión verificada» se guarda por perfil, no por acompañante: al probar el chat
  con un modelo propio, la pantalla de IA puede pedir verificar de nuevo el modelo del perfil.

## Pruebas

- `test/ai_override_test.dart` (7): sin excepción usa el perfil; con excepción usa el modelo del
  acompañante y la clave del perfil; otro acompañante no cambia; se puede borrar; proveedor distinto
  se ignora; la base solo guarda proveedor y modelo; valores con clave o modelo no válido se rechazan;
  el protocolo sigue al modelo en OpenCode.
- `test/ai_per_companion_test.dart` (3): lista y guarda un modelo propio y vuelve al predeterminado;
  un modelo no válido muestra el error en español y no guarda; sin proveedor conectado lo explica y
  queda desactivado.

## Límites

- Solo se elige el **modelo**, no el proveedor: con una sola clave por perfil no hay con qué
  autenticar otro proveedor. Si más adelante el perfil guarda varias claves, `AiOverride.service` ya
  distingue el proveedor.
- Falta la prueba en el teléfono del propietario (recorrido manual: elegir un modelo distinto para un
  acompañante, escribirle y comprobar que responde con ese modelo).
